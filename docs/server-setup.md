
# Практическая работа № 5
## Конфигурация Ubuntu Server

### 1. Виртуальная машина

- Название: devops-vm
- ОС: Ubuntu Server 24.04.5 LTS ARM64
- Платформа: Oracle VirtualBox
- ОЗУ: 2048 МБ
- Процессоры: 2
- Диск: 25 ГБ

### 2. Сеть

- Адаптер 1: NAT — 10.0.2.15/24
- Адаптер 2: Host-only — 192.168.56.2/24
- Проброс портов: 127.0.0.1:2222 → 2222
- Локальное имя: devops.local
- Полное имя сервера: devops-vm.devops.local

### 3. Пользователи

- student — первоначальный пользователь
- devops — пользователь с правами sudo
- SSH-аутентификация по ключу ED25519

### 4. Защита SSH

Файл конфигурации:
/etc/ssh/sshd_config.d/99-hardening.conf

Основные параметры:

- Port 2222
- PermitRootLogin no
- PasswordAuthentication no
- PubkeyAuthentication yes
- MaxAuthTries 3
- AllowUsers devops

### 5. Межсетевой экран UFW

- Статус: active
- Входящие соединения: deny
- Исходящие соединения: allow
- 2222/tcp — LIMIT
- 80/tcp — ALLOW
- 443/tcp — ALLOW

Проверена блокировка входящего TCP-соединения
на порт 8080 с записью UFW BLOCK.

### 6. Снимки VirtualBox

1. 01-clean-install
2. 02-keys-configured
3. 03-ssh-hardened

Для восстановления необходимо выключить ВМ,
открыть вкладку Snapshots в VirtualBox,
выбрать нужный снимок и нажать Restore.

### 7. Аудит

Скрипт: scripts/audit.sh

Проверяет:
- запрет входа root;
- отключение парольной аутентификации;
- порт SSH;
- MaxAuthTries;
- состояние UFW;
- политику входящих соединений.

Успешный аудит: 6 проверок OK, код 0.
Отрицательный тест: FAIL, код 1.

### 8. Вывод

В ходе практической работы настроен Ubuntu Server,
организован защищённый доступ по SSH-ключу,
настроен межсетевой экран UFW и локальное
разрешение имени сервера.

Создан скрипт автоматизированной проверки
параметров безопасности.

## 9. Контейнеризация

### 9.1. Окружение
- ОС: Ubuntu Server 24.04.5 LTS
- Docker Engine: 29.9.2
- Docker Compose: 5.6.1
- Пользователь: devops
- Проект на сервере: /home/devops/app

Docker Engine установлен из официального репозитория Docker.
Пользователь devops добавлен в группу docker.

### 9.2. Приложение
Flask-приложение собирается из Dockerfile на базе python:3.12-slim.
Приложение работает через Gunicorn на порту 5000 от имени
непривилегированного пользователя app.

### 9.3. База данных
Используется PostgreSQL 16-alpine.
В Docker Compose создан сервис db.

Приложение обращается к базе данных по имени db
через внутреннюю сеть app_backend.

### 9.4. Переменные окружения
Файл: /home/devops/app/.env
Права доступа: 600

Файл содержит настройки PostgreSQL и пароль базы данных.
Настоящий пароль создаётся случайным образом и не хранится в Git.

В репозитории находится только шаблон app/.env.example.

### 9.5. Сеть и порты
Создана внутренняя сеть Docker app_backend.

Приложение опубликовано только на:
127.0.0.1:5000

Порт PostgreSQL 5432 наружу не опубликован.

### 9.6. Хранение данных
Для PostgreSQL используется именованный том app_db_data.

Команда docker compose down сохраняет данные.
Команда docker compose down -v удаляет том вместе с данными.

### 9.7. Обратный прокси Nginx
Домен: devops.local

Статический сайт:
https://devops.local/

Flask-приложение:
https://devops.local/app/

Nginx принимает HTTPS-запросы на порту 443
и перенаправляет /app/ на http://127.0.0.1:5000/.

Используется самоподписанный TLS-сертификат.

### 9.8. Основные команды
Запуск:
cd ~/app
docker compose up -d

Проверка:
docker compose ps

Просмотр журналов:
docker compose logs

Остановка:
docker compose down
